# TalentScout — простий довідник по коду та базі даних

Цей документ пояснює, **де що лежить** і **за що відповідає**. Його можна читати зверху вниз перед захистом.

## 1. Де шукати головні речі

```text
TalentScout.sln                         ← відкрити у Visual Studio
TalentScout/
  App.xaml.cs                           ← запуск, DI, шлях до SQLite
  MainWindow.xaml                       ← головне вікно, ліве меню
  Data/                                 ← контекст БД і стартове наповнення
  Models/                               ← класи-дані: анкета, проєкт, навичка
  Repositories/                         ← читання/запис даних у SQLite
  Services/                             ← бізнес-логіка: пошук, фото, кастинг
  ViewModels/                           ← логіка конкретних екранів
  Views/                                ← XAML-екрани
  Resources/Styles/                     ← кольори й стилі інтерфейсу
  Converters/                           ← перетворення шляху до фото в картинку
  Assets/Photos/                        ← фото, вибрані у формах
Data/TalentScout.db                     ← файл SQLite-бази після запуску
Documentation/                          ← документація для захисту
```

## 2. Просте пояснення MVVM

Уявлення про шари:

```text
Користувач натискає кнопку
        ↓
View (XAML) показує форму
        ↓ binding/Command
ViewModel перевіряє дані і викликає потрібний сервіс
        ↓
Service виконує бізнес-дію
        ↓
Repository / EF Core читає або змінює SQLite
        ↓
SQLite файл Data/TalentScout.db
```

Правило: **View не пише SQL, а ViewModel не відкриває SQLite напряму**. Це робить код зрозумілішим і легшим для зміни.

## 4. Data — база даних і її створення

### `Data/TalentScoutDbContext.cs`

Це «карта» бази даних для EF Core.

- Властивість `DbSet<T>` означає таблицю.
- Метод `OnModelCreating` задає ключі, зв’язки, максимальну довжину тексту, індекси та правила видалення.
- Тут є важливе правило: пара «проєкт + талант» у `CastingApplications` унікальна. Через це одну людину не можна двічі додати до одного проєкту.

### `Data/DatabaseInitializer.cs`

Запускається автоматично при старті.

- викликає `EnsureCreatedAsync()` — створює SQLite-таблиці, якщо їх ще немає;
- додає базові навички;
- додає демонстраційні анкети, фото, проєкти й кандидатів, якщо база порожня або в ній їх недостатньо;
- підтримує старі локальні бази, створюючи таблицю користувацьких кольорів за потреби.

## 5. Models — дані предметної області

### `Models/Entities/Talent.cs`

`Talent` — головна анкета людини.

Основні поля: ім’я, прізвище, дата народження, стать, телефон, email, місто, зріст, вага, колір очей і волосся, розміри одягу/взуття, примітки.

Навігаційні властивості:

- `Photos` — усі фото анкети;
- `TalentSkills` — навички людини;
- `CastingApplications` — участь у кастингах;
- `CustomHairColor` — користувацький колір волосся.

Додаткові властивості для UI:

- `FullName` — ім’я і прізвище одним рядком;
- `SkillSummary` — список назв навичок для карток;
- `CanBeAddedToSelectedProject` — тимчасовий прапорець для кнопки «До проєкту», у БД не зберігається.

У цьому ж файлі:

- `TalentPhoto` — шлях до фото, підпис, порядок і позначка головного фото;
- `HairColorOption` — колір, який менеджер додав у довідник.

### `Models/Entities/Skill.cs`

- `Skill` — довідник навичок («Вокал», «Танці» тощо).
- `TalentSkill` — зв’язок «цей талант має цю навичку»; також містить рівень і нотатку.

### `Models/Entities/CastingProject.cs`

У цьому файлі кілька пов’язаних класів.

| Клас | Для чого |
|---|---|
| `CastingProject` | Сам проєкт: назва, клієнт, опис, місто, дата зйомки, статус. |
| `ProjectRequirement` | Вимоги до кандидата: стать, вік, зріст, очі, волосся, примітки. Один проєкт має одну групу вимог. |
| `RequirementSkill` | Зв’язок «ця навичка є вимогою цього проєкту». |
| `CastingApplication` | Один кандидат у одному проєкті та його етап кастингу. |

У `CastingApplication` є зручні властивості для українського UI:

- `StatusLabel`: Запрошений, Проби, Затверджений, Резерв, Відхилений;
- `NextStageLabel`: текст кнопки наступного кроку;
- `CanMoveToNextStage`: чи можна ще рухати кандидата далі.

### `Models/Dtos/TalentSearchCriteria.cs`

DTO для пошуку. Це не таблиця. Він лише передає в сервіс критерії: стать, вік, зріст, волосся й список потрібних навичок.

### `Models/Enums/DomainEnums.cs`

Переліки фіксованих значень: стать, колір волосся, колір очей, рівень навички, статус проєкту, статус кастингу та режим зіставлення навичок.

## 6. Таблиці SQLite: що в них зберігається

| Таблиця | Зміст | Головні зв’язки |
|---|---|---|
| `Talents` | Анкети людей. | 1→багато з фото, навичками й заявками на кастинг. |
| `TalentPhotos` | Шляхи до файлів фото. | Належить одному `Talent`; видаляється разом із ним. |
| `HairColorOptions` | Додані менеджером кольори волосся. | Може бути обраний талантом або вимогою проєкту. |
| `Skills` | Довідник навичок. | Використовується у `TalentSkills` та `RequirementSkills`. |
| `TalentSkills` | Хто які навички має. | Багато-до-багатьох: `Talents` ↔ `Skills`. |
| `CastingProjects` | Кастинг-проєкти. | Має вимогу і багато кандидатів. |
| `ProjectRequirements` | Параметри відбору для проєкту. | Один-до-одного з проєктом. |
| `RequirementSkills` | Навички, які потрібні для проєкту. | Багато-до-багатьох: вимоги ↔ навички. |
| `CastingApplications` | Додавання кандидата в проєкт + його статус. | Зв’язує `Talents` і `CastingProjects`. |

### Схема зв’язків у двох рядках

```text
Talent ──< TalentPhoto
Talent >──< Skill              (через TalentSkills)
CastingProject ──< CastingApplication >── Talent
CastingProject ──  ProjectRequirement >──< Skill (через RequirementSkills)
```

## 7. Repositories — прямий доступ до даних

Інтерфейси лежать у `Repositories/Interfaces`, реальний код — у `Repositories/Implementations`.

| Репозиторій | За що відповідає |
|---|---|
| `TalentRepository` | Отримує анкети з фото й навичками, додає, редагує та видаляє таланти. |
| `SkillRepository` | Повертає довідник навичок і додає нову навичку. |
| `HairColorOptionRepository` | Повертає та додає користувацькі кольори волосся. |
| `ProjectRepository` | Повертає, створює, змінює та видаляє проєкти разом із пов’язаними вимогами/кандидатами. |

Коли треба змінити SQL-логіку читання або збереження — спочатку дивитися саме сюди.

## 8. Services — бізнес-логіка

| Сервіс | Що робить |
|---|---|
| `TalentSearchService` | Будує LINQ-запит до SQLite за критеріями. Вміє шукати за віком, зростом, статтю, волоссям і навичками. |
| `TalentProfileService` | Створює анкету разом з обов’язковим головним фото; якщо запис не вдався, прибирає скопійований файл. |
| `PhotoStorageService` | Копіює обране фото до `Assets/Photos` і повертає відносний шлях. |
| `FilePickerService` | Відкриває стандартне Windows-вікно вибору зображення. |
| `CastingService` | Додає кандидата до проєкту, зчитує склад проєкту та змінює статус одного `CastingApplication`. |
| `DialogService` | Показує діалог підтвердження, наприклад перед видаленням анкети. |

Інтерфейси (`I...Service`) потрібні, щоб ViewModel залежали від абстракції, а не від конкретного класу. Це правильно для MVVM і полегшує тестування.

## 9. ViewModels — логіка екранів

| ViewModel | Екран | Що робить |
|---|---|---|
| `DashboardViewModel` | Огляд | Рахує анкети, проєкти, кандидатів; показує останні анкети та майбутні події. |
| `TalentsViewModel` | Таланти | Завантажує список, додає анкету з фото, навичкою/кольором, відкриває редагування й видаляє анкету. |
| `SearchViewModel` | Пошук талантів | Збирає критерії, запускає пошук, додає людину до вибраного проєкту й вимикає кнопку для вже доданого кандидата. |
| `ProjectsViewModel` | Проєкти | Створює проєкт і його вимоги, показує всі проєкти. |
| `CastingBoardViewModel` | Кастинг-дошка | Завантажує кандидатів проєкту, рухає конкретного кандидата на наступний етап. |
| `SkillOptionViewModel` | Допоміжний | Представляє навичку з прапорцем `IsSelected`. |
| `SelectionOption<T>` | Допоміжний | Дає спискам український напис `Title` і технічне значення `Value`. |
| `ViewModelBase` | Базовий | Спільний базовий клас усіх ViewModel. |

`[ObservableProperty]` і `[RelayCommand]` у ViewModel — атрибути CommunityToolkit.Mvvm. Вони автоматично генерують властивості зі сповіщенням UI та команди для кнопок.

## 12. Якщо треба щось змінити — куди йти

| Завдання | Куди дивитися |
|---|---|
| Змінити вигляд сторінки | відповідний файл у `Views/*.xaml`. |
| Змінити дію кнопки | відповідний `ViewModels/*ViewModel.cs`. |
| Додати поле до анкети | `Models/Entities/Talent.cs` → `TalentScoutDbContext.cs` → форма в `TalentsView.xaml` → `TalentsViewModel.cs`. |
| Додати новий тип пошуку | `TalentSearchCriteria.cs` → `TalentSearchService.cs` → `SearchViewModel.cs` → `SearchView.xaml`. |
| Змінити правила переходу статусів | `CastingBoardViewModel.cs` і `CastingProject.cs` (`CastingApplication`). |
| Змінити створення/наповнення БД | `Data/DatabaseInitializer.cs`. |
| Змінити SQLite-зв’язки та індекси | `Data/TalentScoutDbContext.cs`. |

## 13. Що не варто видаляти

- `Data/TalentScout.db` — це всі локальні дані користувача. Якщо видалити файл, програма створить нову порожню/демо-базу.
- `Assets/Photos/` — фото користувацьких анкет.
- `TalentScout.csproj` — без нього Visual Studio не знає, які бібліотеки потрібні застосунку.
- `App.xaml.cs` — тут налаштовано автоматичне створення БД і всі сервіси.
